Protocol

Semantic correctness and localization quality are evaluated separately

Image tasks combine a semantic decision with target-landmark localization; video tasks combine behavior or visibility predictions with temporal intervals. Scoring these outputs independently reveals how answer correctness relates to spatial and temporal grounding.

Parsing & Validity Rules

All tasks are parsed under strict JSON rules before scoring

Rules

  • The canonical task contract requires strict JSON. A deterministic compatibility audit accepts only documented, unambiguous schema and coordinate variants and applies one rule set to every model run.
  • Image semantic and BBox localization metrics are reported independently; strict semantic-and-localization intersections are retained in the audit snapshot.
  • Video semantic and temporal metrics are reported independently. Behavior intervals are matched one-to-one within the same class, and extra predicted classes count as false positives. Video Dual Evidence requires visibility and every applicable behavior level to reach sample-level F1@0.5 of at least 0.5.
  • The website leaderboard uses convenience aggregate scores for browsing; the raw task-specific metrics remain the primary result source.

Compatibility Audit

Deterministic compatibility rules are applied uniformly by model run

The canonical protocol remains strict. The reported tables additionally use one shared, deterministic compatibility and rescoring pipeline. This pipeline applies to Deterministic compatibility parsing for image outputs, selected-candidate BBox scoring for Future Observation, and class-aware behavior interval matching for video outputs. Coordinate scale is resolved at the model-run level rather than guessed independently for each prediction. Both the original and compatible results are retained for traceability.

5-Stage Fallback Parsing Algorithm

  1. Strict JSON Parse: Execute json.loads(response.strip()). If output matches task schema exactly, return parsed object immediately.
  2. Markdown Codeblock Extraction: If enclosed in markdown code fences (```json ... ```), strip fence delimiters and re-parse.
  3. Balanced Object Extraction: If prose wraps the JSON, scan for the first structurally balanced object while respecting quoted strings.
  4. Key Normalization: Map known synonym keys ("bbox", "box", "bbox_norm" → "bbox_xyxy_norm"; "choice", "answer" → "answer_option_id").
  5. Run-level Coordinate Normalization: Infer one scale for the complete run, convert documented [0,1000] or consistent 640x480 pixel boxes, and reorder reversed corners. Non-finite, out-of-range, or degenerate boxes remain invalid; coordinates are not selectively repaired per sample.

Accepted Forms

  • JSON objects embedded in prose or Markdown fences after removing reasoning tags
  • documented BBox aliases: bbox_xyxy_norm, bbox, bounding_box, and box
  • singleton answers arrays containing one structured prediction
  • native normalized [0,1] BBoxes
  • the documented [0,1000] coordinate convention
  • pixel BBoxes only when the complete run-wide range is consistent with the 640x480 input
  • reversed corner order after deterministic coordinate reordering

Still Invalid

  • ambiguous coordinate scales
  • non-finite, out-of-range, or degenerate boxes
  • outputs without a recoverable JSON object

Image Task Protocols

Image tasks report answer selection and landmark localization separately

Their joint diagnostic is available, but the primary semantic and BBox metrics remain independent so that either failure mode can be inspected directly.

Agent-State Reasoning

Self-relative Position Reasoning

Output Schema

{"answer_option_id":"A","bbox_xyxy_norm":[0.1,0.2,0.3,0.4]}

Valid predictions must provide exactly one option id and one normalized bbox for the target landmark.

Metrics

  • Option Accuracy. Correct relative-position choice.
  • BBox Acc@50IoU. Predicted box overlaps the GT landmark with IoU >= 0.5.
  • BBox Mean IoU. Continuous localization quality on the query image.

Agent-State Reasoning

Action-conditioned Future Observation Prediction

Output Schema

{"answer_option_id":"A","bbox_xyxy_norm":[0.1,0.2,0.3,0.4]}

The BBox is evaluated in the model-selected candidate image. An invalid candidate id or invalid box receives zero localization credit; option correctness is scored independently.

Metrics

  • Option Accuracy. Correct future-view selection under the orbit action.
  • BBox Acc@50IoU. Localization quality in the selected candidate image.
  • BBox Mean IoU. Continuous grounding quality after view prediction.

World-State Reasoning

Landmark-relative Position Reasoning

Output Schema

{"answer_option_id":"A","bbox_xyxy_norm":[0.1,0.2,0.3,0.4]}

Valid predictions must provide exactly one option id and one normalized bbox for the target landmark.

Metrics

  • Option Accuracy. Correct egocentric direction judgment.
  • BBox Acc@50IoU. Localization on the current observation image.
  • BBox Mean IoU. Continuous target grounding fidelity.

World-State Reasoning

Goal-conditioned Action Decision

Output Schema

{"answer_option_id":"A","bbox_xyxy_norm":[0.1,0.2,0.3,0.4]}

Valid predictions must provide exactly one option id and one normalized bbox for the target landmark.

Metrics

  • Option Accuracy. Correct action direction toward the landmark.
  • BBox Acc@50IoU. Localization of the target landmark in the current observation.
  • BBox Mean IoU. Continuous localization quality while making the action decision.

BBox Reference Convention

Every score is evaluated in a defined image coordinate domain

Existing multi-view landmark assets use reviewed boxes enclosing projected visible landmark points. Newly captured environment views use the axis-aligned envelope of in-frustum 3D oriented-box corners; these are geometric projection boxes and need not equal visible-mask tight boxes. Fully in-frame views are preferred, accepted partial projections are clipped to the image boundary, and degenerate or fully out-of-frame boxes are rejected before export.

For Future Observation, the predicted BBox is compared with the landmark box in the model-selected candidate image. Invalid candidate identifiers or invalid boxes receive zero localization credit. Option accuracy is still scored against the correct future view, so the two reported metrics remain independent.

Video Task Protocols

Video tasks separate semantic recognition from interval quality

This is why the benchmark can expose models that recognize the right behavior or count but still misplace the corresponding temporal intervals.

Composite Behavior

Agent-State Video Evaluation

Output Schema

{"answers":[{"option_id":"A","intervals_sec":[[0.0,1.2]]},{"option_id":"C","intervals_sec":[[3.4,5.0]]}]}

Intervals are matched one-to-one only within the same composite behavior class at tIoU >= 0.5; extra classes and intervals count as false positives.

Metrics

  • Composite Accuracy. Exact match between the predicted and ground-truth composite behavior sets.
  • Temporal F1@0.5. Interval-level success at the 0.5 threshold.
  • Mean tIoU. Continuous temporal localization quality.

Atomic Behavior

Agent-State Video Evaluation

Output Schema

{"answers":[{"option_id":"A","intervals_sec":[[0.0,1.2]]},{"option_id":"C","intervals_sec":[[3.4,5.0]]}]}

Intervals are matched one-to-one only within the same atomic behavior class at tIoU >= 0.5; extra classes and intervals count as false positives.

Metrics

  • Atomic F1. Label-set F1 over all predicted and ground-truth atomic behaviors.
  • Temporal F1@0.5. Interval-level success at the 0.5 threshold.
  • Mean tIoU. Continuous temporal localization quality.

Landmark Visibility

World-State Video Evaluation

Output Schema

{"visible_count":2,"visible_intervals_sec":[[0.0,9.1],[17.7,26.8]]}

Visibility count and interval localization are scored independently. Intervals use one-to-one matching at tIoU >= 0.5.

Metrics

  • Count Accuracy. Exact visible-count correctness.
  • Segment F1@0.5. Interval-level visibility success at the 0.5 threshold.
  • Mean tIoU. Continuous temporal overlap quality for visible intervals.

Class-aware Temporal Matching

Behavior identity remains bound to its predicted interval

Composite semantics use exact set accuracy, whereas atomic semantics use label-set F1. Temporal predictions are greedily matched one-to-one only within the same behavior class at tIoU ≥ 0.5. Unmatched and extra predicted classes count as false positives. Visibility intervals use the same one-to-one threshold matching, while visible-count accuracy is scored independently. For video Dual Evidence, visibility and every applicable behavior level must reach sample-level F1@0.5 of at least 0.5.

Matched-context Dual Metrics

Coordination is measured as paired Agent-State and World-State co-success

Image questions are paired within the same scene, Agent–Landmark identity, and difficulty stratum for the position and action–observation task families; paired images can use different UAV poses. Video questions are paired by source trajectory. Dual Semantic Accuracy requires both semantic outputs to succeed, while Dual Evidence Accuracy independently requires both localization outputs to succeed. This matched-context design tests coordinated capability over coordinate-frame reasoning, action–visual association, and behavior–visibility localization through observable task outcomes.

Suffix Handling

Instant/Thinking suffixes are interpreted per model family

The evaluation runtime strips -Instant, -Thinking, or -Reasoning to resolve the base route in common_api_runtime.yaml. It then applies family-compatible request controls (for example enable_thinking, reasoning, or chat_template_kwargs) according to provider capabilities. This keeps the routing contract stable across local deployment and API invocation while preserving a unified experiment naming convention.

Self-relative Position Reasoning

Infer the UAV position relative to the target landmark from a landmark-centric reference view and a current egocentric observation.

Output Schema

{"answer_option_id":"A","bbox_xyxy_norm":[0.1,0.2,0.3,0.4]}

Protocol Note

Agent-State Reasoning image task evaluated with option prediction plus grounding.

System Prompt

[TASK]: You are a UAV agent. Compare a reference view including a landmark and your current first-person view. Decide your position relative to the landmark. [INPUT]: - You are given two first-person view images. - Image 1 is the reference view, showing the landmark and its bounding box. - Image 2 is your current view. - Image 1 tells you which facade of the landmark is visible in the landmark-centric coordinate frame. - The user prompt gives the question and answer options. [OUTPUT]: 1. Return exactly one valid JSON object. 2. Do not output markdown, explanation, or extra text. 3. Use exactly one option_id from the user prompt. 4. The bounding box must use normalized [x1,y1,x2,y2] coordinates. 5. Strictly follow this JSON schema: {"answer_option_id":"A","bbox_xyxy_norm":[0.1,0.2,0.3,0.4]} [NOTE]: 1. Decide your position relative to the landmark in image 2. 2. Also localize the landmark in image 2. 3. The visible facade in image 1 defines the landmark's forward-facing reference.

User Prompt

Image 1 shows the {{reference_object_view}} facade of {{landmark_description}} in the landmark-centric coordinate frame. Based on that reference, what is your position relative to the landmark in image 2? Select one option and return the normalized bounding box of the landmark in image 2. Options: {{options_text}}
